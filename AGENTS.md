## Project Overview

Personal site and guestbook built with Astro 7, TypeScript 7, Tailwind CSS v4, and Cloudflare Workers. Deployed at [its.pabitramohansingh.workers.dev](https://its.pabitramohansingh.workers.dev). Uses D1 (SQLite) for persistence, KV for sessions, and Cloudflare AI (Llama Guard 3) for guestbook message moderation.

## Commands

```bash
pnpm dev              # Start dev server (http://localhost:8787)
pnpm build            # Production build
npx wrangler deploy   # Deploy to Cloudflare
npx drizzle-kit generate  # Generate migrations
npx wrangler d1 migrations apply guestbook-db --local   # Apply locally
npx wrangler d1 migrations apply guestbook-db --remote  # Apply to production
```

## Folder Structure

```text
src/
├── core/       # Shared infrastructure (auth, database)
├── db/         # Drizzle schema and database client
├── features/   # Self-contained feature modules (home, guestbook)
├── layouts/    # Page shell (BaseLayout.astro)
├── pages/      # Routes and API endpoints
├── shared/     # Reusable UI, SEO, scripts, and styles
└── styles/     # Global design tokens and base styles
```

Dependency flow: `pages → layouts → features → shared → core → db`

## Code Style

- TypeScript strict mode.
- PascalCase for `.astro` components. kebab-case for scripts, pages, and CSS files.
- Tailwind utilities inline for layout, spacing, color, and typography.
- External CSS only for pseudo-elements, custom `@keyframes`, descendant selectors, `:nth-child`, and state-driven child styling.
- Never use `!important`. Cascade layers make it unnecessary.
- Never hardcode hex values. Reference design tokens from `src/styles/tokens.css`.
- No comments in code.

## Testing

- No unit test suite configured.
- Verify changes manually via `pnpm dev`.
- Test in both light and dark mode.
- Test the guestbook flow end-to-end: sign in → post → verify moderation.

## Boundaries

### Always do

- Run `pnpm build` before committing to catch TypeScript and Astro errors.
- Test changes in both light and dark mode via `pnpm dev`.

### Ask first

- Modify `src/db/schema.ts` — schema changes require a new migration.
- Change any binding in `wrangler.jsonc` (DB, SESSION, AI, IMAGES, ASSETS).
- Upgrade major versions of Astro, Tailwind CSS, or TypeScript.

### Never do

- Modify the `dist/` folder — generated by `astro build`.
- Touch `.wrangler/` state — managed by Wrangler.

## Security

- Never commit `.dev.vars` — contains development secrets.
- Never hardcode secrets — use `npx wrangler secret put`.
- Never bypass the AI moderation check in `src/pages/api/guestbook.ts`.
- Never log user emails, session tokens, or message content in production.
- Never expose `BETTER_AUTH_SECRET`, `GOOGLE_CLIENT_SECRET`, or `GOOGLE_CLIENT_ID` in client-side code.

## Git Workflow

- Conventional commits: `feat:`, `fix:`, `chore:`, `docs:`, `refactor:`.
- Production branch: `main`. Pushes to `main` auto-deploy via Cloudflare Workers Builds.
- Preview branches create preview versions automatically.
